| `2026-08-04-timing-provenance-and-frame-delivery.md` | implemented | dbdb702 | The probe asked whether packets carried timestamps where the question that decides trust is whether the file supplied them: for `obu`, `mpegvideo`, `yuv4mpegpipe`, `h263` and `jpeg_pipe` the demultiplexer invents one per packet, and `h263` fabricates a rate outright (29.66 frames per second measured for a 25 frames per second source). `MediaFacts.timing_measured` becomes `timing_source` over presentation, decode, synthesized and absent, classified by an explicit list each entry of which was measured by putting non-uniform timing through the format and reading it back. A new reason, `presentation_timing_requires_decode`, routes to a re-encode wherever a stream copy cannot recover the timing -- invented timestamps hide the packet-to-picture mapping, reordering without presentation timestamps hides the order -- because the timestamp-writing remux is a copy and would launder the defect into a derivative that re-probes clean. A source stating no rate in container or bitstream is refused rather than given the muxer's approximation. The frame reader raises where two decoded pictures share one timestamp, the collapse its spacing check cannot see. Implemented. |
| `2026-08-01-deliverable-frame-model-amendments.md` | implemented | 899fc0a | Design changes found while implementing the deliverable frame model, held out of the spec until the implementation confirmed them. Both are folded into the spec, which carries the conclusions; this document keeps the measurements behind them, the alternatives weighed and rejected, and the record of each amendment moving from prediction to measurement. Amendment 1 scopes the frames-preserving decoder flag to a decode segment beginning at the stream start: applied to every container open it corrupts backward-seek landing on an open-GOP source, emitting the previous group's leading pictures against references the seek discarded. Amendment 2 replaces the backstop's two path-specific mechanisms with a per-frame check on delivery: the seek path's landing resolution never inspected the forward count that follows it, and the sequential path's end-of-stream count cannot fire for a bounded window, so a source whose packets do not all decode returned neighboring frames under the requested indices with no error. |
| `2026-08-01-deliverable-frame-model.md` | implemented | 899fc0a | `MediaFacts.frame_count` counts packet timestamps while the frame reader, the transcode output, and any external decoder work in decoded frames, and on real media the two diverge: the reader raises on frames the facts declare, silently returns the wrong frame, or a transcode produces output its own acceptance gate rejects. Every declared frame is now delivered -- through the decoder's frames-preserving flag, through ignoring an edit list whose marks a default decode honors, or by routing an untrusted codec to a derivative that can carry them -- or an error names the reason it cannot be. |
